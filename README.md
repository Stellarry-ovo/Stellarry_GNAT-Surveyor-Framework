# Stellarry_GNAT星球勘测器 v8.1-Framework

Stellarry_GNAT 星球勘测器通过当前运行中的 No Man's Sky 获取星球信息，并提供坐标预览、评分、筛选、结果入库和恢复点坐标跳转功能。

公开版处理总速率上限为每秒 50 颗星球。设置中的“多线程加速”会根据实时 CPU、内存和游戏状态自动调整，并为游戏保留足够的处理能力。

速度上限不是性能承诺。2026-09-20 在目标设备、游戏内部版本 `179292`、V1.6.8 与通用筛选器的实际交集配置下，采用可逆线程调度优化后的 120 秒稳定样本处理 `1378` 颗星球，其中 `230` 颗进入 Lush 完整路径，平均 `11.52` 星球/秒；包含暂停、恢复和停止的控制样本为 `12.63` 星球/秒。非 Lush 星球会在游戏类别阶段直接跳过，不生成后续完整信息；实际速度仍会随 Lush 命中比例、游戏场景和系统负载变化。

筛选器与评分版本会编译成同一份交集计划。根级 `ALL` 条件按依赖成本和预计淘汰率排序，`ANY` 与 `NOT` 保持原子语义，分数/评级条件在结构条件之后执行。当前版本已把 UI 类别选择与模板类别条件的交集下沉到游戏单星球类别阶段；不符合类别的天体不会继续执行后续完整信息路径。草色、叶色和 HQTREE 仍使用游戏返回的真实结果进行后续短路，不会用未经验证的跳转破坏游戏函数生命周期。

勘测热路径只保存当前评分版本与筛选器需要的评分证据、分数、评级和必要身份字段，不构建完整详情。停止勘测后，可在已收录星球详情中点击“生成完整信息”，由当前游戏会话重新生成该星球的全部可用信息并原子升级数据库记录。普通坐标预览仍会直接生成完整信息，但不会入库。

## 详细使用说明

### 首次启动

1. 启动 No Man's Sky 并载入存档，确保角色已经进入游戏世界。
2. 运行 `Stellarry_GNAT星球勘测器.exe`。源码环境可以运行 `启动_Stellarry_GNAT星球勘测器.cmd`。
3. 在一分钟内阅读协议并准确输入“我已确认并同意协议”。
4. 打开设置，在“游戏 NMS.exe”中选择当前 Steam 游戏目录下的 `NMS.exe`。
5. 检查 Steam 存档目录。程序会尝试识别默认路径，也可以手动浏览。
6. 保存设置。

### 游戏更新后的版本校准

1. 启动更新后的游戏并载入存档，停留在可正常操作的游戏画面。
2. 停止当前勘测任务。
3. 打开设置并点击“自动校准游戏版本”。
4. 校准期间不要退出游戏或切换存档。
5. 出现“新版本校准成功并已保存”或“当前版本原本已受支持，复核通过”后即可使用。
6. 如果提示结构变化或校准被拒绝，应等待对应版本适配，不要反复强制尝试。

校准只有在全部检查通过后才会保存；失败不会覆盖以前可用的配置。

### 坐标预览

1. 在顶部坐标框输入十二位十六进制传送门坐标。
2. 选择正确周目并点击生成。
3. 详情栏会显示当前游戏会话返回的目标星球信息。
4. 普通坐标预览不会自动写入数据库。

### 开始勘测

1. 选择评分版本和与其匹配的筛选器。
2. 选择星球类别、周目和最低分。
3. 点击“开始勘测”。
4. 可以随时暂停、继续或停止任务。停止时程序会等待当前游戏函数调用结束，并在游戏侧确认勘测调度恢复空闲后再完成停止。
5. 符合条件的结果会写入程序同目录的 `survey.db`。

### 界面刷新

- 默认使用自动刷新，勘测状态、评级数量和已收录列表会自动同步。
- 在设置中选择手动刷新后，后台勘测继续运行，但界面不会定时读取数据库或重绘列表。
- 手动模式下刷新按钮出现提示点时，点击顶栏刷新按钮即可同步最新状态和结果。
- 手动刷新可以降低 WebEngine 与数据库查询开销；游戏完整信息函数自身的生成时间不受该选项影响。

### 已收录星球与数据库

- 点击评级栏可以查看相应评级结果。
- 首次打开时会自动定位到第一个已有结果的评级；用户主动选择空评级时会保持空列表。
- 点击列表中的坐标可以查看详细信息。
- 新收录记录先显示紧凑评分摘要；停止勘测后点击星球名后的“生成完整信息”，才会向游戏请求全部可用字段、资源信息并升级该条记录。
- HQTREE 树木和部分动物外观由目标星球地表流式加载时产生。若详情提示等待地表采集，请先使用“传送至该坐标”进入目标星球并等待地表载入完成，再次点击“生成完整信息”。程序不会把尚未采到的树木证据误存为“没有树木”。
- 已升级的完整详情会持久化；再次打开不需要重新生成。若游戏返回的坐标、种子或评分证据与原记录不一致，程序会拒绝覆盖。
- `survey.db` 位于发布版 EXE 同目录。
- 完全退出程序后，可以删除 `survey.db` 清空全部记录。
- 程序运行或数据库写入期间不得移动、覆盖或删除数据库。

### 恢复点坐标跳转

1. 在设置中确认游戏程序和存档目录。
2. 填写周目、传送门坐标和玩家 X、Y、Z 坐标。
3. 点击“写入并重载恢复点”。
4. 程序会调用游戏原生恢复点加载流程，无需再打开游戏菜单手动选择“重载恢复点”。
5. 只有游戏完成加载并恢复运行时回调后，界面才会报告跳转成功；超时或游戏退出会显示错误。
6. 本功能只操作恢复点槽，不修改自动存档槽。
7. 执行前应确认当前恢复点可以被覆盖。

### 退出与系统托盘

设置中可以选择每次询问、最小化到系统托盘或直接退出。最小化到托盘后程序仍在后台运行，需要完全关闭时请从托盘菜单退出。

### 常见问题

- 未找到游戏：确认游戏已启动并载入存档，同时检查 `NMS.exe` 路径。
- 版本不受支持：先在设置中执行“自动校准游戏版本”。
- 校准失败：当前更新无法在保证正确性的前提下自动适配，需要等待更新。
- 无法开始勘测：检查评分版本、筛选器、星球类别以及游戏连接状态。
- 恢复点跳转失败：检查存档目录并确认游戏已经载入完成。
- 数据库无法打开：不要同时运行多个勘测器实例，也不要在运行时操作数据库文件。

## 评分版本与筛选器模板制作教程

新建模板统一使用 UTF-8 编码的中文 `.txt` 文件；程序仅为兼容旧数据继续读取 `.json`。在顶栏评分版本或筛选器选项中点击“＋”导入。删除会真正删除程序内的副本，请保留原文件。

评分版本示例：

```text
类型=评分版本
编号=custom.score
名称=自定义评分
说明=示例评分版本
起始分=0

[评分项]
基础分+25
无风暴+20
飞行蠕虫（含眼型）扣分-30

[等级]
S>=110
A>=100
B>=-100
```

筛选器示例：

```text
类型=筛选器
编号=custom.filter
名称=白草高分乐土
说明=白草且评分不低于100分
评分版本=v1.6.8

[条件]
浮花乐土
白草或黄草黄树
评分>=100
树号(1-11,18,19,46,56,68-75)
```

评分版本与筛选器会编译为交集执行计划。生态类型、草色、树叶色和树号等高淘汰率结构条件优先短路，只有依赖评分或评级的条件在评分后执行。

全部中文评分项、筛选字段、树号范围、通用无筛选格式和错误说明见同目录的《评分版本与筛选器模板制作教程.txt》。

## 源码开发与构建

- `main.py`：程序入口。
- `web_ui.py`：内置 WebEngine 界面入口。
- `stellarry_gnat/framework`：协议、模板注册和资源策略。
- `stellarry_gnat/runtime`：游戏会话、版本校准和恢复点服务。
- `stellarry_gnat/search`：坐标选择、限速与任务生命周期。
- `stellarry_gnat/storage`：数据库与坐标去重。
- `stellarry_gnat/ui`：本地接口和 WebEngine 宿主。
- `native_runtime`：运行所需的原生组件。
- `framework_templates`：内置评分版本与筛选器。
- `tools`：测试、源码打包与保护构建工具。

运行 `一键高级保护构建.cmd` 可以生成保护版发布文件。源码环境需要 Python 3.12 及项目构建脚本所列依赖。
# 在线星系上传状态

勘测器会通过游戏当前在线 Discovery 服务查询星系是否已经上传。该系统级字段在评分与筛选之前独立提交，不参与评分，也不会因星球类别早退或筛选淘汰而省略。同一周目、同一星系只提交一次查询，结果会异步更新该星系已经入库的全部星球。

界面使用三态显示：`已上传`、`未上传`、`在线服务未返回`。只有游戏在线服务成功响应时才会产生前两种确定状态；超时、网络失败、服务不可用或游戏退出均显示“在线服务未返回”，不会误判成未上传。
